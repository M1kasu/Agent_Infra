# 02 · User Stories（用户故事）

## 用户角色

| 角色 | 目标 |
| --- | --- |
| 企业员工 | 用自然语言或表单快速报障/申请，看到进度并确认恢复 |
| IT 服务台 | 自动补齐分类、上下文和分派，减少跨团队转单 |
| 专业运维 | 获得有证据的诊断/计划，安全调用设备、身份、SaaS 和基础设施工具 |
| 主管/资源负责人/安全人员 | 对高风险动作看到明确影响和证据并审批 |
| 审计/平台负责人 | 回放任务、评估质量、治理 Skill/Tool/Agent 版本 |

## Story 列表

### US-01 · 多渠道任务输入

作为员工，当我从钉钉、OA、ITSM 或 Element 提交办公故障或服务申请时，我希望系统统一识别人员、地点、设备/应用、现象、影响和期望，从而不用理解后台系统。

### US-02 · 自动采集跨系统上下文

作为服务台，当任务进入系统时，我希望 Context Agent 自动查询相关身份、资产、网络、权限、健康和历史证据，从而减少反复询问和手工跳转。

### US-03 · 专业诊断或变更计划

作为专业运维，当上下文完整时，我希望系统根据场景 Skill 给出可解释的根因、置信度、处置计划、备选方案和影响范围，从而复用团队经验。

### US-04 · 分级自治和人工审批

作为主管或安全人员，当计划包含高风险操作时，我希望看到证据、影响、具体动作、验证条件和补偿方案，并明确批准或拒绝；低风险动作则可按策略自动完成。

### US-05 · 最小权限执行

作为平台负责人，我希望只有 Execution Agent 能调用与当前计划匹配的写工具，并使用幂等键和审计记录，从而避免越权和重复执行。

### US-06 · 独立验证结果

作为员工和运维，当工具返回成功时，我希望系统通过新鲜状态和功能探测验证真实体验是否恢复；未恢复时不得自动关单。

### US-07 · 用户确认与异常升级

作为员工，当系统认为问题已恢复时，我希望收到清晰说明并能确认或反馈仍未解决；系统应把冲突结果升级给人工，而不是循环尝试。

### US-08 · 证据、复盘和能力演进

作为审计或平台负责人，我希望通过 `task_id/trace_id` 回放 Agent、Skill、Tool、审批、执行和验证，并把高质量案例转成评测集、Runbook 或新版 Skill。

| 通用 Story | Docs 账号锁定 | VPN 开通 | 打印机离线 | 会议室投屏 |
| --- | --- | --- | --- | --- |
| US-01 | 员工报告 Docs 不可访问 | 提交资源/端口/期限 | 报告楼层与打印机 | 报告会议室与投屏方式 |
| US-02 | IAM/VPN/权限/健康/探针 | HR/OA/账号组/资源组 | CMDB/队列/网络/耗材 | 预约/设备/网络/日志 |
| US-03 | 判断 account_locked | 生成最小权限 ChangeSet | 判断队列/网络/设备根因 | 判断信号源/网络/固件根因 |
| US-04 | 低风险解锁可自动 | 生产访问需审批 | 重启设备按策略 | 改配置/重启按策略 |
| US-05 | 受限 unlock tool | 创建账号/资源绑定 | 重启队列/设备 | 切换输入/重启设备 |
| US-06 | locked=false 且可访问 | effective access 精确匹配 | 测试页成功 | 画面/探针恢复 |

## 比赛要求映射

| Story | 比赛要求 | 主责 Agent | 验收方式 |
| --- | --- | --- | --- |
| US-01 | 任务输入、规范化 | Manager + Context | 多渠道、多表述输入转为同一 WorkItem Schema（10+ 同义变体验收） |
| US-02 | 上下文、MCP、Evidence | Context | 每项事实带来源、时间、工具调用和 Evidence |
| US-03 | 任务拆解、多 Agent、Skill | Diagnosis & Planning | 结论有证据，计划有目标/步骤/失败处理 |
| US-04 | 审批、安全边界 | Policy & Approval | 未达条件的写调用为 0；审批可回放 |
| US-05 | 工具调用、权限、幂等 | Execution | 重放不产生重复副作用，越权动作被 Gateway 拒绝 |
| US-06 | 结果验证 | Verification | Fake Success 和旧状态不能产生 COMPLETED |
| US-07 | 异常处理、客户确认 | Manager | 用户否认恢复时进入人工升级而非成功关闭 |
| US-08 | Trace、评测、经验沉淀 | Verification + 后置经验管道 | 结论可追溯；案例需评审后才能进入知识/Skill |

## MVP 覆盖

| 用户故事 | 状态 | 说明 |
| --- | --- | --- |
| US-01–US-03（输入、上下文、诊断） | 原型验证 | Element/Matrix 输入，含输入变体集；G06 未知输入、G12 越权分支纳入评测 |
| US-04（策略与审批） | 设计覆盖 + 部分原型 | L1 解锁自动许可、L2 权限授予阻断有设计与代码；真实 Human Approval 交互复赛补 |
| US-05（工具调用与幂等） | 原型验证 | 角色隔离 MCP、越权拒绝、幂等键设计已有 |
| US-06（结果验证） | 设计覆盖 + 部分原型 | Fake Success 检出已在当前 Worker 内实现；独立 Verification Worker 复赛拆出 |
| US-07（用户否认恢复） | 设计覆盖 | 人工升级路径已设计，交互复赛补 |
| US-08（Trace 与经验沉淀） | 设计覆盖 | Trace 已有；经验评审管道复赛实现 |

不以同时接入更多系统替代闭环完整度。
