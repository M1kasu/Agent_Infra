# 09 · Security Design（安全与审批设计）

> 危险操作必须有人类在环。这既是评分项，也是演示红线：演示中必须能真实看到"Agent 请求 → 人批准 → 才执行"。
> 状态：⬜ 未开始 · 负责人：待认领 · [← 返回 README](../README.md)

## 危险操作分级

| 等级 | 定义 | 示例 | 处置方式 |
| :-- | :-- | :-- | :-- |
| L0 只读 | 无副作用 | 查询指标、日志、知识库 | 直接执行，留痕 |
| L1 可逆写 | 可撤销 | 生成报告、写注释 | 记录后执行 |
| L2 危险 | 影响真实系统 | 重启、扩容、改配置 | **人工审批后执行** |

## 权限模型

- 哪些 Agent 持有写权限？为什么最小化？
- Mock 工具是否也要走审批？（建议：是，保持演示真实性）

## 审计与留痕

所有 ToolCall 必须可回溯：谁（Agent）、何时、调了什么工具、输入输出、结果、关联 Evidence ID（实体定义见 [03 领域模型](03-domain-model.md)）。

## 密钥管理

- 密钥只存 `.env`（已在 `.gitignore` 中排除），仓库内只出现 `.env.example`
- 任何人不得把真实密钥写进文档、代码、截图
